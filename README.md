# Embedded — прошивка STM32F3 Discovery

> *Данный README.md сгенерирован с использованием нейросетевой модели от OpenAI «GPT-5.6 Luna» на основе анализа структуры проекта и проверен автором.*

Прошивка для платы **STM32F3 Discovery** на базе микроконтроллера STM32F303. Текущая конфигурация считывает данные со встроенных инерциальных датчиков **L3GD20** (гироскоп) и **LSM303DLHC** (акселерометр), фильтрует их и передаёт по USART1.

Проект выполнен как bare-metal-приложение без RTOS: аппаратные прерывания обслуживают таймеры и приём USART, а основная обработка выполняется в бесконечном цикле `main()`.

## Возможности
- период запуска измерений — 200 Гц;
- фильтрация акселерометра и гироскопа простым фильтром Калмана;
- адаптивное масштабирование показаний датчиков при инициализации;
- передача IMU-пакетов и текстовых сообщений по USART1;
- приём команд через прерывание USART и разделение команд на срочные и отложенные;
- две стадии работы: `FooStage` и `MeasureStage`;
- индикация состояния встроенными светодиодами платы;
- отладка и загрузка через OpenOCD.
## Логика работы
После старта прошивка:
1. копирует таблицу векторов прерываний и настраивает SysTick с периодом 1 мс;
2. инициализирует светодиоды, USART и датчики;
3. запускает `FooStage`;
4. после команды перехода в `MeasureStage` включает TIM2 и TIM4;
5. каждые 5 мс считывает датчики, применяет фильтры, формирует пакет и отправляет его по USART1.

`TIM2` формирует частоту измерений 200 Гц и устанавливает флаг готовности. `TIM4` используется для периодического мигания светодиодами. Непосредственное чтение датчиков выполняется в основном цикле, а не в обработчике прерывания таймера.
## Команды

| Команда         | Тип        | Действие                      |
| --------------- | ---------- | ----------------------------- |
| `FF FF`         | срочная    | перезагрузка микроконтроллера |
| `AA 01`         | отложенная | переход в `FooStage`          |
| `AA 02`         | отложенная | переход в `MeasureStage`      |
| `CONFIRM`       | отложенная | отправка подтверждения        |
| `HANDSHAKE_REQ` | отложенная | отправка `IMU_STM32_ACK`      |
| `HEARTBEAT_REQ` | отложенная | отправка `IMU_STM32_ALIVE`    |

Срочная команда выполняется в контексте USART IRQ. Остальные команды помещаются в SPSC-кольцевой буфер ёмкостью 8 элементов и исполняются в основном цикле.
## Формат исходящих пакетов
Все пакеты начинаются с общего заголовка `C8 8C`, за которым следуют байт формата, длина полезных данных, сами данные и контрольная сумма — младший байт суммы всех предыдущих байтов.
### Пакет IMU

```text
header[0..1]  : C8 8C
format        : 01
data_length   : длина полезных данных
package_num   : uint32_t, счётчик измерений
acc_data      : float x, float y, float z
gyro_data     : float x, float y, float z
control_sum   : uint8_t
```
Структура упакована через `#pragma pack(1)` и передаётся как непрерывный буфер. При текущем составе полей размер пакета составляет 33 байта.

### Текстовое сообщение
```text
header[0..1]  : C8 8C
format        : CD
data_length   : длина текста
text          : до 32 байт
control_sum   : uint8_t
```

```text

│   └── inc/
│       ├── aaa_Project_Files/  команды, декодер и IMU-пакет
│       ├── Common/             общие типы и константы
│       ├── Communication/      USART, USB VCP, сообщения и пакеты
│       ├── DataContainers/     очереди и кольцевые буферы
│       ├── Filters/            фильтры и статистические утилиты
│       ├── Periph/             GPIO, EXTI и светодиоды
│       ├── Sensors/             обёртки L3GD20 и LSM303DLHC
│       └── Timers/              обёртки таймеров STM32
├── system/                 CMSIS, startup, SPL, системные и USB-файлы
├── make/                   Makefile и правила компиляции
├── ldscripts/              linker scripts и карта памяти
├── Debug_Win/              объектные и итоговые файлы Windows-сборки
├── md files/               архитектурные и аппаратные заметки
```

Большинство пользовательских модулей реализовано в header-only стиле. В текущей конфигурации Makefile компилирует один пользовательский исходник — `user/src/main.cpp`; библиотечный код находится в `system` и собирается из C/C++ исходников.

## Сборка
Для сборки нужны:
- ARM GNU Toolchain с `arm-none-eabi-gcc`, `arm-none-eabi-g++` и `arm-none-eabi-objcopy`;
- GNU Make или `mingw32-make`;
- Windows-конфигурация, рассчитанная на toolchain в `C:/SysGCC/arm-eabi`;
- для загрузки — OpenOCD и отладчик ST-LINK.

Из корня проекта пример полной сборки:
```powershell
mingw32-make -C make -f Makefile.mk build_all `
  SYSTEM=windows `
  PROGRAM_NAME=ImuReading `
  SOURCE_DIR=D:/Job/AsyncReadingData/Embedded
```

Основные цели Makefile:
```text
build_all     полная сборка библиотек и пользовательского кода
rebuild_all   очистка и полная пересборка
build_user    сборка пользовательского кода и линковка
rebuild_user  пересборка пользовательского кода и линковка
clean_all     удаление объектных и итоговых файлов
```

Результаты сборки появляются в `Debug_Win/`: ELF-файл, HEX-файл и map-файл. Имя файлов задаётся переменной `PROGRAM_NAME`; значение по умолчанию в `make/make_args.mk` и имя в `.vscode/settings.json` сейчас различаются, поэтому при ручной сборке имя лучше задавать явно.

В VS Code доступны задачи полной пересборки, сборки пользовательских файлов и загрузки через OpenOCD. Конфигурация запуска отладчика находится в `.vscode/launch.json`.

## Прошивка через OpenOCD

После сборки ELF-файла можно выполнить загрузку командой вида:
```powershell
openocd.exe -f path/to/stm32f3discovery.cfg `
  -c "program Debug_Win/ImuReading.elf verify reset exit"
```
Конкретные пути к OpenOCD, GDB и SVD-файлу задаются в `.vscode/settings.json`.
