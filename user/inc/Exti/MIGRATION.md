# Миграция модуля EXTI на другой МК

Инструкция относится к заголовкам каталога `user/inc/Exti`. Исходная реализация
рассчитана на STM32F303, SPL STM32F30x и CMSIS для Cortex-M. Назначение классов
и пример использования приведены в [README.md](README.md).

Конкретный целевой МК здесь не выбран. Перед изменением кода нужно сопоставить
описанные ниже зависимости с документацией выбранного МК и используемой библиотеки.
Замена подключаемых заголовков сама по себе не завершает перенос.

## 1. Зафиксировать целевую конфигурацию

Составить таблицу по reference manual, datasheet, errata, документации и заголовкам
периферийной библиотеки целевого МК:

| Параметр | Что определить |
| --- | --- |
| МК и корпус | Доступные порты и выводы, ограничения выбранного корпуса. |
| Ядро | Совместимость с Cortex-M, наличие используемых CMSIS API и модели NVIC. |
| Инструменты | Компилятор, стандарт C++, версия периферийной библиотеки и CMSIS. |
| Маршрутизация | Как выбирается порт для линии EXTI, какой блок и его тактирование нужны. |
| События | Поддерживаемые фронты, режимы interrupt/event, программное инициирование события. |
| IRQ | Какие линии объединены в векторы и какая другая периферия использует эти векторы. |
| Pending | Регистры, банки, способ проверки и очистки, отдельные флаги фронтов при их наличии. |
| Аргументы API | Где ожидается номер линии, где битовая маска или другой идентификатор. |
| Приоритеты | Число реализованных битов и поддержка группировки приоритетов. |
| Таблица векторов | Способ её размещения, изменения и подключения к ядру. |

На основе этой таблицы согласовать необходимые изменения архитектуры и публичных
типов. Внешние зависимости модуля проверяются отдельно; автоматически менять
`BaseIRQDevice` и другие общие классы при переносе EXTI не следует.

## 2. Сохранить принятые контракты

- `GPIO_Pin_EXTI` объединяет настройку GPIO и EXTI и содержит приватный объект
  `GPIO_EXTI_n<тип пина>`. Регистрация отделена от пользовательской функции.
- `GPIO_EXTI_n` получает аппаратные сведения через `EXTI_Descriptor` и использует
  существующий CRTP-механизм `BaseIRQDevice`.
- Таблица обработчиков общая для разных типов пинов. Нельзя превращать её в
  отдельный статический массив каждой специализации `GPIO_EXTI_n<PinExti_t>`.
- Конфликт ресурса обнаруживается при регистрации: повтор того же переходника
  успешен, другая функция на занятой линии возвращает `false`.
- Объекты существуют всё время работы IRQ; копирование, перемещение и динамическая
  отмена регистрации не входят в текущий контракт.
- Все источники общего IRQ обслуживаются одним маршрутом. Регистрация другого
  пина не должна исключать из обработки ранее зарегистрированные линии.
- Настройка приоритета относится ко всему вектору. Новая регистрация без явных
  параметров не должна сбрасывать его настройки.
- Обработка выполняется в контексте IRQ, без динамической памяти и виртуальной
  диспетчеризации. Pending очищается до пользовательской функции, если такой
  порядок допускает целевая периферия.

Логический интерфейс желательно сохранить: объявление типа через `using`, создание
объекта, `InitPinExti()`, `GenerateSWInterrupt()` и `SetInterruptPriority()`.
Однако текущий публичный API принимает типы SPL: `GPIOMode_TypeDef`,
`GPIOPuPd_TypeDef`, `EXTI_InitTypeDef`, `NVIC_InitTypeDef` и другие. При переходе
на другую библиотеку совместимость этих параметров нужно решить явно. Изменение
только внутренней реализации не гарантирует совместимость прикладного исходного кода.

## 3. Адаптировать файлы

### Exti.hpp — аппаратный дескриптор и настройка линии

1. Заменить подключения SPL на заголовки целевой платформы.
2. Обновить `EXTI_Descriptor::IRQn` по таблице векторов нового МК.
3. Обновить `EXTI_Descriptor::PortSource`: значения источников портов могут
   отличаться от перечисления `GPIO_Port` и друг от друга на разных платформах.
4. Адаптировать `GPIO_EXTI::InitExti()`: выбор порта, настройку фронтов, режима
   и разрешения источника. Проверить дополнительные поля структуры инициализации.
5. Адаптировать `GenerateSWInterrupt()` и условия, при которых программное
   событие приводит к входу в IRQ.

Текущая реализация передаёт номер линии 0…15 в API EXTI напрямую. Для нового API
при необходимости вводится явное преобразование в аппаратную маску или идентификатор.
Одного `static_cast` недостаточно для преобразования номера в битовую маску.
Такое преобразование должно быть согласовано для инициализации, проверки pending,
очистки и программного события.

### ExtiPin.hpp — прикладная обёртка и порядок инициализации

1. Согласовать `GPIO_Pin` и `GPIO_PortDescriptor` с целевым GPIO. Эти классы
   находятся вне каталога EXTI и являются отдельными зависимостями переноса.
2. Обновить включение тактирования блока маршрутизации. Сейчас используется
   `RCC_APB2PeriphClockCmd(RCC_APB2Periph_SYSCFG, ENABLE)`; это привязка к STM32F303.
3. Адаптировать проверку `EXTI_InitStructure_ptr->EXTI_Line`: она должна сравнивать
   настройку с нужной линией в представлении нового API.
4. Проверить диапазон `pin_source`, `static_assert` и значения GPIO по умолчанию.
5. Сохранить проверку конфликта до изменения маршрутизации и конфигурации GPIO.
6. Обеспечить готовность таблицы, объекта регистрации и маршрута IRQ до того,
   как прерывание сможет вызвать пользовательскую функцию.

В текущем коде регистрация NVIC предшествует настройке GPIO и EXTI, а весь участок
защищён сохранением `PRIMASK` и запретом маскируемых IRQ. При переносе сохранить
этот эффект либо согласовать другой порядок, исключающий преждевременный вызов.
На всех выходах восстанавливать исходную маску; не добавлять безусловный
`__enable_irq()` после `__set_PRIMASK()`.

### ExtiIRQ.hpp — регистрация и учёт настроенных векторов

1. Проверить тип `IRQn`, проверку номера канала в пользовательской структуре NVIC
   и вызов `BaseIRQDevice::InitInterrupt()`.
2. Пересчитать `vector_index` для новой группировки линий.
3. Согласовать с ним `vector_mask` и размер `initialized_vectors` в диспетчере.
4. Адаптировать `SetInterruptPriority()` к числу битов приоритета и доступным
   средствам контроллера прерываний. Текущий код использует `NVIC_SetPriority()`,
   `NVIC_EncodePriority()` и `NVIC_GetPriorityGrouping()`.

`vector_index` — внутренний индекс вектора, а не числовое значение `IRQn`.
Сейчас линии 0…4 используют биты 0…4, группа 5…9 — бит 5, группа 10…15 — бит 6.
Семь состояний помещаются в `uint8_t`. Если векторов станет больше восьми,
нужно изменить тип хранилища и типы масок, а не только формулу индекса.

### ExtiIRQDispatcher.hpp — pending, групповые IRQ и общая таблица

1. Проверить размер `irq_vectors[16]` и ограничение `pin_source >= 16`.
   Таблица сейчас предназначена для GPIO-линий; внутренние источники EXTI
   автоматически к ней не добавляются.
2. Обновить `switch` в `dispatch_irq()` и диапазоны проверяемых линий.
   Обрабатывать все сработавшие источники группы, а не только первый найденный.
3. Заменить `EXTI_GetITStatus()` и `EXTI_ClearITPendingBit()` с учётом банков,
   масок разрешения и правил записи в регистры нового МК.
4. Если используются отдельные pending-флаги нарастающего и спадающего фронтов,
   определить их проверку и очистку. Текущий callback сообщает о событии линии
   без отдельного параметра, обозначающего фронт.
5. Сохранить очистку обслуживаемого события перед callback. Не очищать заодно
   чужие линии или новые события способом, противоречащим правилам периферии.

Соответствие линий векторам нужно обновлять согласованно в трёх местах:
`EXTI_Descriptor::IRQn`, `dispatch_irq()` и расчёте `vector_index`.

### Совмещённый вектор TSC

В текущем коде `EXTI2_TS_IRQn` указан в базовом классе диспетчера, объявлении
дружбы с `BaseIRQDevice`, входном `irq_handler()` и `switch`. В
`RegisterTSCHandler()` дополнительно задана маска `1U << 2`.
Все эти места должны соответствовать карте векторов целевого МК.

Сохранить следующие свойства при наличии TSC:

- GPIO EXTI2 и TSC используют общий маршрут, не перезаписывая обработчики друг друга.
- Регистрация TSC работает без созданного GPIO-пина EXTI2.
- Оба порядка регистрации — сначала GPIO и сначала TSC — сохраняют оба источника.
- Функция TSC проверяет и очищает собственные флаги; она может быть вызвана из-за GPIO.
- `RegisterTSCHandler()` регистрирует функцию и при необходимости настраивает NVIC,
  но не включает источники прерываний внутри TSC.

Если TSC отсутствует, имеет отдельный вектор или делит IRQ с другими блоками,
согласовать новую маршрутизацию и судьбу `RegisterTSCHandler()`. Нельзя оставлять
несуществующий `EXTI2_TS_IRQn` или возвращать успех для неподдерживаемой функции.
Разработка самого драйвера TSC не является частью переноса GPIO EXTI.

## 4. Проверить внешнюю инфраструктуру

После согласования проверить вне этого каталога:

- `GPIO_Pin`, `GPIO_PortDescriptor` и совместимость типа `handler_t`.
- Регистрацию в `BaseIRQDevice`: обработчик и его объект должны быть готовы до
  разрешения аппаратного IRQ; сохранённый адрес объекта должен оставаться действительным.
- Активную таблицу векторов: доступность для изменения, выравнивание, размер,
  способ выбора таблицы ядром и соответствие индексов периферийным IRQ.
- Startup-код, линкерное размещение и отсутствие другого обработчика, который
  независимо присваивает ту же ячейку таблицы.
- Пути поиска заголовков: новые и старые версии с одинаковыми именами и include guards
  не должны случайно подменять друг друга.

Перенос на другое ядро требует отдельного решения для замены NVIC, `PRIMASK`
и модели регистрации векторов. Изменения общего `BaseIRQDevice` предварительно
согласовываются; формально похожие имена API не доказывают совместимость.

## 5. Проверки готовности переноса

После реализации выполнить согласованные сборку и аппаратные проверки.
Этот список описывает необходимые проверки, а не подтверждает их выполнение.

| Проверка | Ожидаемый результат |
| --- | --- |
| Сборка и линковка | Все используемые специализации и пример из README собираются для выбранного МК. |
| Отдельная линия | Физический фронт вызывает только нужную функцию. |
| Общий вектор | Каждый пин группы работает, в том числе после регистрации других пинов. |
| Одновременные события | Обрабатываются все ожидающие линии, их pending корректно сбрасываются. |
| Конфликт линии | Попытка регистрации другого переходника возвращает `false` и не меняет маршрутизацию. |
| Повторная регистрация | Тот же переходник принимается без потери других источников. |
| Приоритет | Новая регистрация с настройками по умолчанию сохраняет общий приоритет; явное изменение действует на весь IRQ. |
| Маска прерываний | Успешный и ошибочный выходы сохраняют исходный `PRIMASK`, включая изначально запрещённые IRQ. |
| Программное событие | `GenerateSWInterrupt()` вызывает нужный маршрут при разрешённых источниках. |
| Повторная инициализация | Сброс накопленного pending соответствует принятому контракту. |
| TSC, если поддерживается | Работает отдельно и совместно с EXTI2, в обоих порядках регистрации. Нет повторных входов из-за неочищенного источника. |

Обновить пример, ограничения и аппаратные сведения в README и Doxygen-комментариях.
Зафиксировать целевой МК, версию библиотеки и результаты реально выполненных проверок.
