# Внешние прерывания GPIO (EXTI)

Заголовки для работы с EXTI на STM32F303 через SPL. Прикладной код задаёт порт,
номер вывода и пользовательский обработчик; настройка GPIO, маршрутизация EXTI
и регистрация IRQ скрыты за `GPIO_Pin_EXTI`.

Реализация зависит от конкретного МК. При переносе предполагается сохранять
прикладной интерфейс, адаптируя аппаратную часть библиотеки.

## Файлы

| Файл | Содержимое и назначение |
| --- | --- |
| [Exti.hpp](Exti.hpp) | `STM_EXTI::EXTI_Descriptor<port, pin_source>` определяет `IRQn` и `PortSource`. `STM_EXTI::GPIO_EXTI` связывает порт с линией, настраивает EXTI и предоставляет `GenerateSWInterrupt()`. |
| [ExtiPin.hpp](ExtiPin.hpp) | `STM_GPIO::GPIO_Pin_EXTI<port, pin_source, external_irq_handler>` наследует `GPIO_Pin` и `GPIO_EXTI`, содержит приватный объект регистрации `GPIO_EXTI_n`. Основной прикладной интерфейс. |
| [ExtiIRQ.hpp](ExtiIRQ.hpp) | `STM_EXTI::GPIO_EXTI_n<PinExti_t>` получает параметры из типа пина, регистрирует его статический переходник и настраивает вектор через внешний `BaseIRQDevice`. |
| [ExtiIRQDispatcher.hpp](ExtiIRQDispatcher.hpp) | Нешаблонный `STM_EXTI::EXTI_IRQ_Dispatcher` хранит общую таблицу из 16 функций, отдельный обработчик TSC, состояние настройки семи векторов и распределяет события между источниками. |

Все пространства имён указаны относительно `STM_CppLib`.

## Пример использования

Обработчик, тип и объект пина объявляются на уровне файла. В примере PC5
используется как источник EXTI5; объект существует всё время работы МК.

```cpp
#include "ExtiPin.hpp"

void button_irq_handler(){
    // Короткая пользовательская обработка события EXTI5.
}

using ButtonPin_t = STM_CppLib::STM_GPIO::GPIO_Pin_EXTI<
    STM_CppLib::STM_GPIO::GPIO_Port::PortC,
    GPIO_PinSource5,
    button_irq_handler
>;

ButtonPin_t button_pin;
```

После настройки системного тактирования вызвать из `main()` функцию инициализации:

```cpp
bool init_exti_pins(){
    if (!button_pin.InitPinExti(GPIO_Mode_IN, GPIO_PuPd_DOWN)){
        return false;
    }

    button_pin.SetInterruptPriority(1, 0);
    return true;
}
```

Вход PC5 получает подтяжку к земле, прерывание возникает по нарастающему фронту.
`false` сообщает об ошибке инициализации, которую должен обработать вызывающий код.
Приоритет `1, 0` применяется ко всему `EXTI9_5_IRQn`; вызов
`SetInterruptPriority()` можно опустить, чтобы использовать значения по умолчанию.
Флаг EXTI очищает диспетчер, поэтому в `button_irq_handler()` повторно очищать его
не требуется.

## Инициализация и обработка

Конструктор пина создаёт объект регистрации, но не включает аппаратуру.
`InitPinExti()` вызывается после создания всего объекта из основного кода:

1. Проверяет соответствие пользовательских настроек линии и IRQ типу пина.
2. Регистрирует статический переходник и при необходимости настраивает NVIC.
3. Настраивает GPIO, включает тактирование SYSCFG через APB2, очищает старый
   pending-флаг и настраивает EXTI.
4. Восстанавливает сохранённый `PRIMASK` и возвращает `true`.

При конфликте регистрации или несовпадении линии/IRQ метод возвращает `false`
до изменения аппаратных настроек. По умолчанию GPIO настроен как вход без
подтяжки, EXTI — как разрешённое прерывание по нарастающему фронту.

Путь аппаратного события:

```text
BaseIRQDevice
    → GPIO_EXTI_n::irq_handler()
        → EXTI_IRQ_Dispatcher::dispatch_irq(IRQn)
            → проверка и очистка pending-флага линии
                → GPIO_Pin_EXTI::irq_handler()
                    → external_irq_handler()
```

| Линии GPIO | Вектор NVIC | Обработка |
| --- | --- | --- |
| 0, 1, 3, 4 | Соответствующий `EXTI0_IRQn`, `EXTI1_IRQn`, `EXTI3_IRQn`, `EXTI4_IRQn` | Проверяется одна линия. |
| 2 | `EXTI2_TS_IRQn` | Проверяется GPIO EXTI2, затем вызывается обработчик TSC, если он зарегистрирован. |
| 5…9 | `EXTI9_5_IRQn` | Последовательно проверяются все пять линий. |
| 10…15 | `EXTI15_10_IRQn` | Последовательно проверяются все шесть линий. |

## Принятые ограничения

- Объекты пинов и регистрации существуют всё время работы соответствующих IRQ.
  Копирование и перемещение запрещены; API отмены регистрации отсутствует.
- Одна линия EXTI имеет одного владельца. Например, PA5 и PC5 нельзя использовать
  одновременно как независимые источники EXTI5. Разные линии общего IRQ допустимы.
- Занятость проверяется во время выполнения при регистрации. Повтор той же
  функции-переходника успешен; другая функция на занятой линии отклоняется.
  Отдельной проверки конфликтов при компиляции нет.
- Таблица общая для всех специализаций `GPIO_EXTI_n`, а не отдельная для каждого
  типа пина. Динамическая память и виртуальные вызовы не используются.
- Обработчик выполняется в контексте IRQ. Рекомендуется ограничивать время его
  работы и избегать блокирующих операций. Pending очищается перед вызовом функции,
  даже если для линии нет зарегистрированного обработчика. Pending не является
  счётчиком: несколько фронтов могут объединиться в одно ожидающее событие.
- Инициализация выполняется с запрещёнными маскируемыми прерываниями. Вложенные
  операции восстанавливают исходный `PRIMASK`; безусловный `__enable_irq()` после
  восстановления не требуется. При повторной настройке нужно учитывать задержку IRQ
  и сброс накопленного pending-флага.
- Приоритет принадлежит вектору. `SetInterruptPriority()` после инициализации
  меняет его для всех линий группы. Первая настройка использует значения
  `BaseIRQDevice` по умолчанию либо явно переданную структуру NVIC. Последующая
  регистрация с `nullptr` сохраняет настройки; явная структура позволяет их изменить.
- При самостоятельном использовании `GPIO_EXTI::InitExti()` тактирование SYSCFG
  нужно включить заранее. Обёртка `GPIO_Pin_EXTI` делает это сама.

### Touch Sensing

Вектор `EXTI2_TS_IRQn` совмещён с TSC. Для регистрации функции TSC предусмотрен
`EXTI_IRQ_Dispatcher::RegisterTSCHandler(handler_t handler)`: повтор той же функции
успешен, `nullptr` или другая функция при занятой регистрации дают `false`.

Общий диспетчер сначала обрабатывает GPIO EXTI2, затем вызывает функцию TSC.
Она должна проверять и очищать собственные флаги, учитывая, что вход в IRQ мог
быть вызван GPIO. Регистрация должна работать и без созданного пина EXTI2.
Источники прерываний TSC включаются отдельно; драйвер TSC в состав каталога не входит.

## Адаптация под другой МК

Пошаговая инструкция и проверки переноса приведены в [MIGRATION.md](MIGRATION.md).

Перенос требует согласованных изменений нескольких мест:

1. **Порты и линии:** проверить допустимые GPIO, маршрутизацию источника,
   настройку тактирования и `EXTI_Descriptor::PortSource`. Согласовать внешние
   реализации `GPIO_Pin` и `GPIO_PortDescriptor` с новым МК.
2. **Группировка IRQ:** обновить `EXTI_Descriptor::IRQn`, диапазоны в `dispatch_irq()`
   и расчёт `vector_index` в `GPIO_EXTI_n::InitInterrupt()`. Последний сейчас кодирует
   пять отдельных векторов и две группы в семи битах `initialized_vectors`.
3. **API периферии:** заменить подключения и вызовы SPL. Текущий код передаёт в EXTI
   номер линии 0…15; у другой библиотеки аргумент может быть битовой маской.
   Проверить правила чтения pending, учёт разрешения источника и очистку флагов.
4. **Совмещённые источники:** учесть периферию, разделяющую IRQ с EXTI, включая TSC.
   Нельзя независимо перезаписывать общий вектор обработчиками разных устройств.
5. **Ядро и таблица векторов:** проверить внешнюю реализацию `BaseIRQDevice`,
   доступность CMSIS API, приоритеты NVIC и возможность изменения активной таблицы
   векторов. `PRIMASK`, NVIC и используемая модель регистрации привязаны к Cortex-M.

После переноса нужны сборка и аппаратная проверка одиночных и групповых IRQ,
одновременных событий, конфликтов линий, сохранения приоритетов и маски прерываний.
Эти проверки не заменяются чтением исходников.

## Подключение

Путь `user/inc/Exti` должен участвовать в поиске заголовков вместе с каталогами
зависимостей. Внешние подключения `GpioPin.hpp`, `GpioPort.hpp`, `BaseIRQDevice.hpp`
и `Consts.hpp` остаются необходимыми.

Прикладной `GPIO_Pin_EXTI` подключается через `ExtiPin.hpp`.
