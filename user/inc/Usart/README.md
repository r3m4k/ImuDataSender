# USART для STM32F303

Модуль предоставляет три самостоятельных прикладных класса:

- `UsartTx<Type, TxPin, TxBufferSize>` — передача из программной очереди через IRQ.
- `UsartRx<Type, RxPin, Decoder>` — приём байтов пользовательским декодером в IRQ.
- `UsartTxRx<Type, TxPin, RxPin, Decoder, TxBufferSize>` — оба направления с одной регистрацией.

Типы находятся в `STM_CppLib::STM_Usart`. Прикладные классы не наследуются друг
от друга: аппаратный компонент, TX/RX-каналы и регистрация объединены композицией.
Динамическая память и виртуальная диспетчеризация не используются.

TX-канал владеет TX-пином, очередью и аппаратными операциями передачи. RX-канал
владеет RX-пином, декодером и аппаратными операциями приёма. Оба канала зависят
от STM32/SPL. Общий аппаратный компонент задаёт тактирование, скорость и формат
слова, включает и выключает весь USART. Прикладное устройство согласует работу
только тех направлений, которые входят в его тип.

## Подключение и пример

Каталог `user/inc` уже присутствует в путях поиска заголовков проекта. Подключать
новый модуль следует явно через `Usart/…`; добавлять каталог перед старым
`Communication/Usart` в список путей не требуется.

```cpp
#include "Usart/UsartTx.hpp"
#include "Usart/UsartRx.hpp"
#include "Usart/UsartTxRx.hpp"

using namespace STM_CppLib::STM_Usart;

struct ExampleDecoder{
    void byte_processing(uint8_t byte){
        // Короткая обработка входного байта в контексте USART IRQ.
        (void)byte;
    }
};

using TxPin_t = STM_CppLib::STM_GPIO::GPIO_Pin<
    STM_CppLib::STM_GPIO::GPIO_Port::PortC, GPIO_PinSource4>;
using RxPin_t = STM_CppLib::STM_GPIO::GPIO_Pin<
    STM_CppLib::STM_GPIO::GPIO_Port::PortC, GPIO_PinSource5>;

// Три альтернативных типа для USART1; создаётся и инициализируется один из них.
using TxPort_t = UsartTx<UsartTypes::Usart1, TxPin_t, 256>;
using RxPort_t = UsartRx<UsartTypes::Usart1, RxPin_t, ExampleDecoder>;
using Port_t = UsartTxRx<UsartTypes::Usart1, TxPin_t, RxPin_t, ExampleDecoder, 256>;

Port_t port;

bool init_port(){
    if (!port.Init({.baudrate = UsartBaudRate::Baudrate_115200})){ return false; }
    port.SetInterruptPriority(1, 0);
    return true;
}

bool send_data(){
    const uint8_t data[] = {0x10, 0x20, 0x30};
    return port.SendBuffer(data, sizeof(data));
}
```

Объект создаётся на всё время работы МК. До `Init()` необходимо настроить
системное тактирование и установить RAM-таблицу `_user_vector_table` в `VTOR`,
как того требует внешний `BaseIRQDevice`. Конструкторы не обращаются к регистрам.
`Init()` запускает модуль; для RX отдельное разрешение приёма не требуется.

Последовательность `Init()`:

1. Проверить скорость и зарегистрировать владельца аппаратного ресурса.
2. Через `Stop()` остановить устройство; при активном аппаратном TX/RX вернуть `false`.
3. Скопировать конфигурацию и задать в её поле `direction` значение `DIRECTION`
   своего канала либо объединение `tx_channel_t::DIRECTION | rx_channel_t::DIRECTION`
   для TX/RX. Передать полученную конфигурацию в общую настройку USART.
4. Инициализировать пины и состояние только присутствующих каналов. TX сохраняет
   очередь; RX сохраняет декодер и очищает старые аппаратные данные и ошибки.
5. Запустить общий модуль, разрешить RX-источники при наличии приёмника,
   возобновить TX-очередь при наличии передатчика и разрешить вектор NVIC.

`DIRECTION` — статическая аппаратная маска TX или RX, необходимая `USART_Init()`.
Поле `direction` служебное: `Init()` задаёт его по типу устройства в локальной копии,
сохраняя исходный объект конфигурации. Значение, переданное вызывающим кодом,
заменяется маской каналов. Для отдельного преобразования конфигурации в SPL его
значение по умолчанию равно TX | RX. Общий аппаратный компонент передаёт маску в SPL
однократно и не хранит отдельного поля `mode`. Проверки наличия направления во время
выполнения отсутствуют. Повторный `Start()` уже
работающего устройства возвращает `true` без перенастройки каналов и источников IRQ.

Преобразование прикладных полей в значения SPL выполняет
`explicit operator USART_InitTypeDef() const`. Аппаратный компонент вызывает его
через `static_cast<USART_InitTypeDef>(config)`. Оператор возвращает полностью
заполненный `USART_InitTypeDef`, включая направление, и не обращается к аппаратуре.
При чётности Even/Odd выбирается аппаратное слово 9 бит для сохранения 8 полезных бит.
Oversampling отсутствует в этой структуре SPL и применяется аппаратным компонентом
отдельно, до `USART_Init()`. `UsartConfig` зависит от SPL из-за оператора преобразования
и маски направлений; при переносе на другую библиотеку или МК их также нужно адаптировать.

Скорость, формат и oversampling передаются одним объектом `UsartConfig`. Его значения
по умолчанию — 115200 бит/с, 8N1, Oversampling16; для них достаточно `port.Init({})`.
Например, 57600 бит/с и 8E2 задаются так:

```cpp
UsartConfig config{
    .baudrate = UsartBaudRate::Baudrate_57600,
    .parity = UsartParity::Even,
    .stop_bits = UsartStopBits::Two
};
bool configured = port.Init(config);
```

`UsartBaudRate` содержит именованные скорости 9600, 19200, 38400, 57600,
115200, 230400, 460800 и 921600 бит/с. Перечисление не гарантирует достижимость
скорости при выбранном тактировании: аппаратная проверка выполняется в `Init()`.
Метод `validate_baudrate(UsartBaudRate, UsartOversampling)` проверяет только диапазон
делителя при текущем тактировании. Второй параметр по умолчанию равен
`UsartOversampling::Oversampling16`. Все три прикладных класса передают ему
`config.oversampling`; общая настройка использует то же поле. Для Oversampling16
рассчитывается `round(clock / baudrate)`, для Oversampling8 —
`round(2 * clock / baudrate)`. В обоих случаях допустим диапазон 16...65535 до
кодирования BRR. Бит OVER8 задаётся до вызова `USART_Init()`, а SPL выполняет
кодирование BRR для выбранного режима. Допустимая погрешность фактической скорости
не проверяется.
Поля `UsartConfig` должны содержать только объявленные значения соответствующих
перечислений; проверка их принадлежности перечислению во время выполнения не выполняется.

Восемь полезных бит сохраняются с чётностью: аппаратная длина слова в этом случае
равна девяти битам. Девять полезных бит, RTS/CTS и специальные режимы USART в API
не входят. После изменения системного тактирования USART нужно настроить заново.

Для выбора Oversampling8:

```cpp
bool configured = port.Init({
    .baudrate = UsartBaudRate::Baudrate_921600,
    .oversampling = UsartOversampling::Oversampling8
});
```

Oversampling8 позволяет повысить предельную скорость по тактированию, но уменьшает
допустимое расхождение частот отправителя и приёмника по сравнению с Oversampling16.
Смена режима через повторный `Init()` подчиняется тем же проверкам активности TX/RX.

## Контракт API

| Метод | Поведение |
| --- | --- |
| `Init(const UsartConfig& config)` | Принимает скорость и формат одним объектом, проверяет настройки и владение, переинициализирует и запускает модуль. `false` при неподдерживаемых настройках, другом владельце или аппаратной активности TX/RX. |
| `Start()` | Возобновляет работу и сохранённую TX-очередь. `false` до успешного `Init()`. Повтор при работающем модуле успешен. |
| `Stop()` | `false` при аппаратной активности; иначе останавливает модуль, сохраняя очередь и декодер. До инициализации возвращает `true`. |
| `SetInterruptPriority(preemption_priority, subpriority = 0)` | Меняет приоритет всего вектора после `Init()`. До регистрации ничего не делает. |
| `IsTxBusy()` | Для TX и TX/RX: последняя аппаратная передача ещё не завершена по TC. Программная очередь в проверку не входит. |
| `IsRxBusy()` | Для RX и TX/RX: аппаратура принимает отдельное слово по признаку BUSY. Не означает приём целого пакета или наличие байта в RDR. |
| `SendByte(byte)` | Для TX и TX/RX: добавляет байт в очередь. |
| `SendBuffer(data, size)` | Для TX и TX/RX: копирует массив целиком либо возвращает `false` без частичной записи. |
| `SendPackage(package)` | Для TX и TX/RX: обёртка для существующего `Packages::BasePackage`. |
| `SendMessage(message)` | Для TX и TX/RX: обёртка для существующего `BinaryData::MutableByteView`. |
| `GetTxFreeSpace()` | Для TX и TX/RX: число свободных байтов программной очереди. |
| `GetTxBufferedDataSize()` | Для TX и TX/RX: число байтов только в программной очереди, без TDR и сдвигового регистра. |

Размер TX-буфера — степень двойки от 2; полезная ёмкость `TxBufferSize - 1`.
Запросы размера выполняются из main и дают снимок состояния: IRQ может сразу
извлечь следующий байт. Пустая очередь совместима с `IsTxBusy() == true`.
Для полного завершения всех принятых данных из main проверяются оба условия:

```cpp
bool all_sent = port.GetTxBufferedDataSize() == 0 && !port.IsTxBusy();
```

Отправка разрешена только после запуска. Нулевой размер успешен у работающего
порта, в том числе с `nullptr`; непустой массив с `nullptr` отклоняется.
Успех отправки означает копирование в очередь. Исходный массив можно сразу
переиспользовать. При нехватке места приложение должно обработать `false`.

## Повторная инициализация и остановка

Непустая очередь не запрещает повторный `Init()` и `Stop()`, если аппаратный
передатчик свободен. При переинициализации оставшиеся байты передаются с новыми
настройками. Декодер сохраняет состояние; неполный пакет автоматически не сбрасывается.
Непрочитанное аппаратное слово RX и старые ошибки при перенастройке сбрасываются.
Остановка сама по себе не очищает программную очередь и не снимает регистрацию.

Прикладной класс выполняет проверку аппаратной активности и отключение устройства
в одной короткой критической секции, исключающей запись TDR обработчиком TX.
`UsartTx` проверяет и останавливает TX-канал, `UsartRx` — RX-канал, `UsartTxRx` —
оба. Сначала отключаются источники IRQ каналов, затем общий USART. Исходный
`PRIMASK` восстанавливается. Копирование массива, настройка GPIO и общей
конфигурации SPL не выполняются под общей маской IRQ. При отказе `Init()`/`Stop()`
рабочие настройки сохраняются.

`IsRxBusy()` является моментальным снимком: между словами возможен `false`,
хотя отправитель продолжает пакет. Программная маска IRQ не останавливает
внешнего отправителя. Для гарантированной смены формата или скорости нужна
согласованная пауза на линии; проверка BUSY не устраняет начало нового слова
непосредственно после чтения флага.

## Регистрация и обработка IRQ

```text
Аппаратный вектор
  → BaseIRQDevice<UsartIRQVector<IRQn>, IRQn>
  → UsartIRQDispatcher: все зарегистрированные модули данного IRQ
  → статический переходник конкретного устройства
  → TX-канал, затем RX-канал для UsartTxRx
  → аппаратные операции соответствующего канала
  → пользовательский декодер для принятого байта
```

Таблица владельцев общая для всех типов устройств, размеров очередей, пинов и
декодеров. Регистрируется пара «адрес устройства + статический переходник».
Другая пара на занятом модуле получает `false` до изменения аппаратных настроек.
Повтор той же пары успешен. Два объекта одного типа также считаются разными владельцами.

Первый источник устанавливает переходник и приоритеты `BaseIRQDevice` по умолчанию.
Приоритет принадлежит вектору. Следующая регистрация и повторный `Init()` его не
сбрасывают. `Stop()` отключает источники только своего USART, не запрещая общий
вектор NVIC и не очищая его pending. На STM32F303 перечисленные пять модулей
имеют отдельные USART/UART IRQ; диспетчер проверяет все совпадающие привязки и
при адаптации способен обслуживать несколько USART одного IRQ.

Общие операции NVIC находятся в `BaseIRQDevice` и доступны наследникам через
`protected`: `register_interrupt()`, `set_interrupt_priority()`,
`enable_interrupt()` и `disable_interrupt()`. Регистрация только записывает
CRTP-переходник в RAM-таблицу. Установка приоритета не меняет разрешение вектора,
а включение/выключение сохраняет приоритет и pending. Глобальная маска IRQ
этими операциями не изменяется.

При первой установке `UsartIRQVector` запрещает свой вектор, регистрирует
переходник и задаёт приоритет по умолчанию. После настройки USART и каналов
вектор разрешается отдельным вызовом базового класса. `UsartIRQ.hpp` не выполняет
прямых вызовов NVIC. Таблица владельцев и признак первой настройки остаются
общими в `UsartIRQDispatcher`.

Совмещённый `BaseIRQDevice::InitInterrupt()` сохранён с прежним поведением для
таймеров, EXTI и старого USART. Их перевод на раздельный API выполняется отдельно.

Правила флагов зависят от USART:

- RXNE обслуживается чтением RDR до вызова декодера.
- TXE обслуживается записью TDR. При опустошении очереди TXE отключается,
  разрешается TC последнего слова.
- TC отключается как источник IRQ, но флаг завершения остаётся установленным.
  Это позволяет `IsTxBusy()` проверять аппаратное состояние даже до обслуживания TC IRQ.
- PE/FE/NE/ORE из снимка ISR очищаются записью в ICR до вызова декодера.
  Слово с PE/FE/NE отбрасывается. При ORE уже находящееся в RDR слово передаётся
  декодеру, потерянные следующие данные восстановить нельзя. Счётчики ошибок
  и отдельный пользовательский API ошибок не предусмотрены.

## Ограничения и переход со старого модуля

- Управление, отправка и запросы размера выполняются из основного кода. Единственный
  писатель TX — main, единственный читатель — USART IRQ. Отправка из декодера RX
  или другого IRQ нарушает контракт SPSC и не поддерживается.
- Декодер создаётся без аргументов, предоставляет `void byte_processing(uint8_t)`
  и выполняет короткую неблокирующую обработку в IRQ. RX-очередь отсутствует.
- Копирование и перемещение устройств запрещены. После регистрации устройство
  не должно уничтожаться. Удаление, автоматическая отмена регистрации и восстановление
  прежнего вектора не реализованы.
- Выводы и их допустимость выбирает приложение. Дескриптор использует AF7 для
  USART1–3 и AF5 для UART4–5; выбранная пара должна поддерживать именно этот AF.
  Арбитраж GPIO между разными периферийными модулями отсутствует.
- `main.cpp` намеренно оставлен на старом `Communication/Usart`. Старые файлы
  и их незавершённые изменения сохранены. Новый модуль пока не подключён приложением.
  Старые и новые заголовки USART нельзя смешивать: имена типов и include guard
  пересекаются. Старые классы не участвуют в новой таблице владения и не должны
  работать одновременно с новыми на одном аппаратном модуле.
- До миграции приложения необходимо убрать отправку подтверждения срочной
  перезагрузки из RX IRQ в `DecoderImu`. При переносе отправки в main сброс МК
  должен происходить после опустошения очереди и физического завершения TX.

## Адаптация под другой МК

1. Обновить `UsartDescriptor`: доступные модули, адреса, IRQ, тактирование,
   частоты и AF. Согласованно обновить индексы и список ресурсов диспетчера.
2. Адаптировать `UsartHardware`: общую настройку USART, допустимые форматы,
   расчёт скорости и включение/выключение модуля.
   Преобразование полей в аппаратную конфигурацию находится в операторе `UsartConfig`
   и при смене SPL или МК адаптируется отдельно.
3. Адаптировать `UsartTxChannel` и `UsartRxChannel`: настройку их GPIO/AF,
   маски `DIRECTION`, признаки аппаратной активности, доступ к данным,
   управление источниками IRQ и правила очистки флагов.
4. Проверить группировку IRQ. Все источники совмещённого вектора, включая
   периферию другого вида, должны обслуживаться общим переходником. Если такой
   источник не USART, его поддержку нужно добавить при адаптации.
5. Проверить внешние GPIO, CMSIS/NVIC, приоритеты и механизм RAM-векторов
   существующего `BaseIRQDevice`. При смене ядра заменить короткие критические секции.
6. Сохранить прикладные классы, методы и контракт декодера; отдельный универсальный
   HAL и дополнительные уровни наследования для этого не требуются.
